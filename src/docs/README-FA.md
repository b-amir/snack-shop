# اسنک‌شاپ - دموی فروشگاه اینترنتی (نسخه فارسی)

این پروژه یک نمونه اپلیکیشن فروشگاه اینترنتی با استفاده از Next.js و کشینگ Redis را به نمایش می‌گذارد. هدف آن **شبیه‌سازی یک بازار آنلاین بزرگ (بیش از ۲۰ هزار محصول، بیش از ۵ میلیون کاربر)** است که در آن سرعت بارگذاری صفحات و عملکرد سرور اهمیت حیاتی دارد.

## معماری اصلی

- **فریم‌ورک**: Next.js 15 (App Router)
- **کشینگ**: استراتژی کشینگ مبتنی بر Redis برای داده‌های محصولات و پاسخ‌های API
- **رندرینگ**: رویکرد رندرینگ ترکیبی (Hybrid) بهینه‌سازی شده برای هر نوع صفحه
- **چندزبانه (i18n)**: پشتیبانی از انگلیسی و فارسی با استفاده از `next-intl`
- **مدیریت وضعیت (State Management)**: داده‌های سبد خرید در `Redis` ذخیره شده و در سمت کلاینت با `Zustand` مدیریت می‌شود.
- **تست**: تست‌های واحد (Unit) و End-to-End با `Jest` و `Cypress`

## محدودیت‌های عمدی

برای کاهش پیچیدگی و حجم باندل، محدودیت‌های زیر در نظر گرفته شده است:

- **استفاده حداقلی از کتابخانه‌های خارجی**
- **عدم استفاده از کتابخانه‌های UI**: فقط از CSS Modules برای استایل‌دهی استفاده شده است.
- **عدم وجود احراز هویت**: تنها از یک کوکی session id برای پیگیری سبد خرید استفاده می‌شود.
- **عدم وجود آنالیتیکس**: برای شبیه‌سازی محصولات پربازدید، ۸ محصول جدیدتر کش می‌شوند.
- **عدم وجود دیتابیس**: برای سادگی، از یک فایل JSON برای ذخیره داده‌های محصولات استفاده می‌شود.

## الگوهای رندرینگ

هر نوع صفحه از استراتژی رندرینگ خاصی در Next.js استفاده می‌کند که با کشینگ Redis تقویت شده است:

- **صفحات لیست محصولات (PLP - `/`)**:
  - **استراتژی Next.js**: Dynamic Rendering با **Incremental Static Regeneration (ISR)** (بازسازی حداکثر هر ۶۰ ثانیه).
  - **کشینگ Redis**: پاسخ‌های API لیست محصولات برای **۵ دقیقه** کش می‌شوند (`PRODUCT_LIST_CACHE_TTL`).
- **صفحات جزئیات محصول (PDP - `/products/[productId]`)**:
  - **استراتژی Next.js**: **Static Site Generation (SSG)** در زمان build برای ۸ محصول جدیدتر + **ISR** برای تمام صفحات (بازسازی حداکثر هر ۱ ساعت). `dynamicParams = true` اجازه ساخت صفحات دیگر در اولین درخواست را می‌دهد.
  - **کشینگ Redis**: پاسخ‌های API جزئیات محصول برای **۳۰ دقیقه** کش می‌شوند (`PRODUCT_DETAIL_CACHE_TTL`).
- **سبد خرید و پرداخت**:
  - **پیاده‌سازی**: سمت کلاینت با Zustand برای مدیریت وضعیت.
  - **پایداری**: داده‌های سبد خرید با Redis برای ثبات همگام‌سازی می‌شوند.

## بهینه‌سازی‌های عملکرد

### معماری کشینگ چندلایه

1.  **لایه ISR در Next.js**: کش کردن صفحات رندر شده.
2.  **لایه کش Redis**: کش کردن پاسخ‌های API قبل از رسیدن به Next.js.
3.  **لایه CDN/Edge**: (در صورت دیپلوی روی پلتفرمی مثل Vercel) کش شدن صفحات ISR در لبه شبکه.

### استراتژی کشینگ Redis

- **لیست محصولات**: کش برای **۵ دقیقه** (`PRODUCT_LIST_CACHE_TTL`).
- **جزئیات محصول**: کش برای **۳۰ دقیقه** (`PRODUCT_DETAIL_CACHE_TTL`).
- **محصولات مرتبط**: کش برای **۱۵ دقیقه** (`RELATED_PRODUCTS_CACHE_TTL`).
- **کلیدهای کش ساختاریافته**: برای ابطال هدفمند (مانند `products:{page}:{pageSize}:{sort}`).

### فرآیند گرم کردن کش (Cache Warming)

یک worker مجزا (`src/workers/cacheWarmer.ts`) هر ۱۰ دقیقه داده‌های کلیدی را در Redis پیش‌بارگذاری می‌کند:

1.  صفحه اول پیش‌فرض محصولات.
2.  جزئیات هر محصول در آن صفحه.

### ابطال کش (Cache Invalidation)

یک endpoint امن (`/api/revalidate`) ابطال دوگانه انجام می‌دهد:

1.  ابطال کش Redis برای محصول و لیست‌های مشخص.
2.  فعال کردن بازسازی مسیر (path revalidation) در Next.js.
3.  امن‌سازی با احراز هویت مبتنی بر توکن.

### مکانیزم Fallback

یک کش درون حافظه (in-memory) ساده در صورت عدم دسترسی به Redis فعال می‌شود.

### بهینه‌سازی تصاویر

- استفاده از کامپوننت `next/image` برای بهینه‌سازی خودکار.
- Lazy loading برای تصاویر پایین صفحه.
- امکان استفاده از Cloudinary CDN (با تنظیم فلگ در env).

### تمرکز بر Core Web Vitals

- بهینه‌سازی LCP, CLS, FID.

### بهینه‌سازی کد

- استفاده از کامپوننت‌های اشتراکی.

## اجرای پروژه

**۱. اپلیکیشن اصلی:**

```bash
# نصب وابستگی‌ها
npm install

# اجرای سرور توسعه
npm run dev

# --- یا ---

# بیلد برای پروداکشن
npm run build

# اجرای سرور پروداکشن
npm start
```

**۲. Worker گرم کردن کش (اختیاری):**

```bash
# اجرای worker در حالت توسعه
npm run cache:warm:dev

# --- یا ---

# اجرای worker در حالت پروداکشن
npm run cache:warm:prod
```

## تست

- **تست‌های واحد (Unit Tests)**: با Jest برای تست توابع و کامپوننت‌ها.
- **تست‌های End-to-End (E2E)**: با Cypress برای جریان‌های کاربری حیاتی.

```bash
# اجرای تست‌های واحد
npm run test:unit

# اجرای تست‌های E2E
npm run test:e2e
```

## پیکربندی

فایل `.env.example` را به `.env.local` در ریشه پروژه کپی کرده و متغیرهای لازم را تنظیم کنید:

```env
# لازم برای اتصال به Redis
REDIS_URL=redis://localhost:6379

# اختیاری: استفاده از Cloudinary CDN برای تصاویر
# اگر false باشد، از بهینه‌سازی next/image استفاده می‌شود
NEXT_PUBLIC_USE_CLOUDINARY_CDN=true

...

```

## ساختار پروژه

```
├── src/
│   ├── app/            # صفحات App Router نکست، layoutها و روت‌های API
│   ├── components/     # کامپوننت‌های UI قابل استفاده مجدد
│   ├── data/           # فایل داده products.json
│   ├── features/       # ساختار پوشه مبتنی بر فیچر
│   ├── i18n/           # تنظیمات و دیکشنری‌های محلی‌سازی
│   ├── services/       # سرویس‌های API و داده
│   ├── store/          # استور Zustand برای مدیریت سبد خرید
│   ├── types/          # تعریف تایپ‌های TypeScript
│   ├── utils/          # توابع کمکی
│   └── workers/        # Workerهای پس‌زمینه برای گرم کردن کش
├── public/             # فایل‌های استاتیک
├── cypress/            # تست‌های E2E
```
